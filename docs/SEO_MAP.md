# خريطة SEO والملاحظات الحالية

هذا المستند يصف التنفيذ الموجود في المصدر، وليس اعتمادًا لصحة كل ادعاء تسويقي أو طبي. تحقّق من مالك الموقع قبل تغيير معلومات العيادة أو الأسعار أو النتائج.

## أماكن إدارة SEO

| النطاق | الملف/المكوّن | ما يديره |
|---|---|---|
| HTML الأولي | `index.html` | لغة/اتجاه الصفحة الافتراضي، title/description/keywords وOpen Graph/Twitter وcanonical أولي وJSON-LD للعيادة |
| Metadata حسب المسار | `SEOManager` في `src/App.tsx` | عناوين وأوصاف وكلمات مفتاحية وصورة المشاركة وcanonical وhreflang وبيانات منظمة وBreadcrumbList |
| بيانات الصفحة الرئيسية | `src/pages/Index.tsx` | Metadata وبيانات منظمة إضافية للصفحة الرئيسية |
| تفاصيل الخدمة | `src/pages/ServiceDetail.tsx` | عنوان ووصف وkeywords وDentist/MedicalProcedure JSON-LD |
| المعرض والحالة | `src/pages/Portfolio.tsx` و`src/pages/CaseDetail.tsx` | Metadata للمعرض والحالة ومشاركة الحالة وبيانات منظمة |
| الصفحات الأخرى | صفحات مثل `About.tsx`, `Contact.tsx`, `AllServices.tsx` | بعض الصفحات تضيف Helmet أو canonical وبيانات Open Graph محلية |
| المدونة | `src/pages/BlogSEO.tsx` | أداة تعديل وسوم المقالات؛ تحقق من موضع استدعائها قبل الاعتماد عليها |

`App.tsx` يحتوي خريطة metadata لبعض المسارات، ثم يستخدم بيانات الصفحة الرئيسية كقيمة احتياطية للمسارات غير الموجودة في الخريطة. ويُحدّث كذلك مشاهدة الصفحة في Google Analytics عند تغيّر المسار.

## خريطة المسارات القابلة للفهرسة

| المسار | المحتوى المقصود | ملاحظة SEO |
|---|---|---|
| `/` | الرئيسية/العيادة والخدمات | بيانات أولية في `index.html` ثم Metadata ديناميكية |
| `/about` | التعريف بالعيادة | يوجد canonical محلي في `About.tsx` على نطاق مختلف عن النطاقات الأخرى |
| `/services` | قائمة الخدمات | Metadata محلية وعامة متداخلة |
| `/services/:serviceId` | خدمة مفردة | يعتمد المحتوى على `servicesData`; الخدمات غير المعرفة تعرض حالة غير موجودة |
| `/portfolio` | معرض الأعمال | بيانات الحالات ثابتة؛ راجع موافقات استخدام صور المرضى |
| `/case/:id` | حالة منفردة | metadata تعتمد على بيانات الحالة |
| `/blog` | قائمة المقالات | محتوى القائمة ثابت داخل الصفحة |
| `/blog/:postId` | مقال | التنفيذ الحالي يستخدم محتوى تجريبيًا واحدًا رغم اختلاف `postId` |
| صفحات التواصل والحجز والاستشارة | تحويلات/معلومات اتصال | راجع صفحاتها لوجود Metadata محلية واتساق البيانات |

## القياس والتتبع

- `index.html` يضمّن Google Tag Manager، وGoogle Analytics 4، وMeta Pixel مع معرفات التتبع.
- `src/App.tsx` يرسل حدث `page_view` عند تغيّر المسار إذا كانت `window.gtag` متاحة.
- تغييرات التتبع أو الموافقة على ملفات الارتباط ينبغي أن تُراجع مع مالك التحليلات وسياسة الخصوصية.

## مخاطر واتساق يجب مراجعتها

1. **النطاق الأساسي غير موحد:** تظهر نطاقات مختلفة في canonical وOG وJSON-LD، منها `dr-khashaba.com` و`www.dr-khashaba.com` و`drkhashaba.com` ونطاق فرعي آخر في صفحة التعريف. اختر نطاقًا أساسيًا واحدًا، ثم وحّد جميع المراجع بعد تأكيد الملكية وإعادة التوجيه.
2. **مسارات اللغة غير متوافقة:** `App.tsx` ينشئ رابط `hreflang` إنجليزيًا على `/en${pathname}`، لكن Router لا يعرّف بادئة `/en`؛ تبديل اللغة يتم داخل التطبيق على المسار نفسه. لا تُعلن عن نسخ URL غير موجودة.
3. **تغطية metadata متفاوتة:** الخريطة في `App.tsx` لا تغطي كل المسارات الديناميكية (`/services/:serviceId`, `/case/:id`, `/blog/:postId`) كمدخلات ثابتة، وبعض الصفحات تضيف وسومًا متعارضة أو canonical خاصًا بها. اختبر الناتج الفعلي لكل مسار ولغة.
4. **صفحة المقال:** مسارات المقالات لا تختار محتوى مستقلًا حاليًا، وهذا يضعف uniqueness للمحتوى والعناوين والبيانات المنظمة.
5. **وسوم أولية/مكررة:** Metadata موجودة في HTML وفي أكثر من Helmet. تحقق من DOM النهائي بعد الانتقال بين الصفحات لتفادي تكرار الوسوم أو بقاء قيمة سابقة.
6. **بيانات منظمة متعددة:** يوجد Dentist/MedicalOrganization/ProfessionalService وبيانات Breadcrumb/Service/Procedure في أكثر من موضع. وحّد الاسم والعنوان والهاتف وساعات العمل والنطاقات قبل التعديل؛ بعض الصفحات تحتوي أمثلة/قيمًا افتراضية.
7. **ملفات الزحف:** لا تظهر ملفات `sitemap.xml` أو `robots.txt` ضمن ملفات `public/` الحالية. أضفها بعد اعتماد قائمة المسارات canonical، وليس قبلها.
8. **محتوى طبي وتسويقي:** راجع صحة الأسعار والضمانات ومدة النتائج وأرقام الحالات والساعات والادعاءات المقارنة قبل نشرها؛ التوثيق لا يثبت صحتها.
9. **الكلمات المفتاحية:** توجد قوائم طويلة ومتكررة في Metadata. حافظ على عنوان ووصف موجزين وفريدين ومفيدين للزائر؛ لا تعتمد على `meta keywords` كبديل عن محتوى الصفحة.
10. **الوسائط:** لكل صورة مهمة نص بديل وصفي مناسب، وصور الحالات لا ينبغي فهرستها/نشرها إلا وفق سياسة الخصوصية والموافقة.

## ترتيب عملي للتحسين

1. تأكيد النطاق الرسمي وبيانات العيادة مع المالك.
2. إعداد خريطة canonical واحدة تغطي المسارات الفعلية، وإزالة canonical المتضارب.
3. تحديد استراتيجية URL للإنجليزية ثم توحيد `hreflang` والروابط الداخلية وفقها.
4. فصل Metadata لكل صفحة/خدمة/حالة/مقال عن الخريطة العامة ومنع سقوط الصفحات إلى Metadata الرئيسية.
5. ربط كل `postId` بمقال حقيقي ذي محتوى وعنوان ووصف فريدين.
6. مراجعة JSON-LD باستخدام البيانات المعتمدة وإزالة القيم الافتراضية أو غير المؤكدة.
7. إنشاء sitemap/robots بعد اعتماد المسارات، ثم التحقق من الروابط والـ metadata لكل صفحة في بيئة الإنتاج.
8. مراجعة الأداء، الصور، النصوص البديلة، التوافق مع الهاتف، وإعدادات التحليلات/الخصوصية.

## فحوصات يدوية قبل النشر

- افتح كل مسار مباشرًا وتأكد أن إعادة كتابة SPA تعمل.
- افحص `title`, `description`, `canonical`, `hreflang`, OG/Twitter وJSON-LD في DOM النهائي لكل لغة.
- اختبر روابط canonical و`hreflang`؛ يجب أن تعيد صفحات موجودة ومكافئة.
- تحقق أن كل صورة/فيديو مستخدم موجود، وأن محتوى الحالة معتمد للنشر.
- تأكد أن قيمة analytics والـ pixels تخص الحسابات الصحيحة وسياسة الموافقة المناسبة.
